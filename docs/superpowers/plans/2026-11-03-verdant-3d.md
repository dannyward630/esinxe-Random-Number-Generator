# Verdant 3D Implementation Plan

> **For agentic workers:** Use independent parallel work for scene terrain,
> actor art and jump simulation, then a fresh whole-branch review. Root owns
> renderer/camera/input integration, hosting and browser acceptance.

**Goal:** Ship the existing expedition as an inviting, playable 3D adventure.
**Architecture:** Three.js draws streamed seeded chunks and mutable actors;
the existing simulation retains horizontal identity and save progress. Pure
spatial helpers tie terrain geometry, camera controls and picking together.
**Tech Stack:** JavaScript modules, Three.js 0.187.0, native dialog, Web Workers.
**Spec:** docs/superpowers/specs/2026-11-03-verdant-3d-design.md

## Global constraints

Preserve existing saves/story paths and frozen generator. No runtime CDN.
Use Luna 6 Max only for subagents. Ship and verify the public Pages deployment.

## Review focus

Camera-relative movement must stay normalized at every yaw; negatives and
chunk boundaries must not shift rendering/picking; menus must freeze jumping
and breath; evicted chunks must dispose GPU resources; WebGL failure must leave
a working game and explicit compatibility controls.

## Verification

Run `npm test --prefix JavaScript`, `npm run typecheck --prefix JavaScript`,
`python scripts/check_repo.py`, Python site tests and Ruff. Node geometry tests
must exercise real Three.js objects without requiring GPU. Browser acceptance
exercises actual WebGL rendering and controls. Record evidence in
`docs/VERDANT_ACCEPTANCE.md` without claiming universal device performance.
